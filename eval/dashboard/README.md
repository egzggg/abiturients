# Eval Studio

Локальная админ-панель для сравнения embedding-моделей RAG Abitura.
Стек: Next.js App Router, React, TypeScript, Tailwind CSS, локальные компоненты
shadcn/ui на Radix и Framer Motion.

## Запуск на macOS

Нужны Node.js 20.9 или новее и npm. Проверить версии можно в Terminal:

```bash
node --version
npm --version
```

Из корня репозитория выполните:

```bash
cd eval/dashboard
npm ci
npm run dev
```

Откройте http://127.0.0.1:3000. Остановить сервер можно сочетанием Ctrl+C в
терминале, где он запущен. Команда `npm run start` запускает production-сборку
после `npm run build`.

На Windows используйте PowerShell:

```powershell
cd eval/dashboard
npm.cmd ci
npm.cmd run dev
```

Скрипты `dev` и `start` слушают только локальный адрес `127.0.0.1`.

## Что доступно

- Обзор: выбор датасета результатов, метрики выбранной модели, график Hit/MRR по
  top-k, время кодирования запроса и таблица последних результатов всех моделей
  и вариантов промптов из сохранённых отчётов.
- Новый эксперимент: повторный запуск E5 Large на Golden/SQuAD. Отчёты E5 Instruct, Qwen3 0.6B, GTE, Qwen3 GGUF и ONNX int8 доступны для просмотра; модели с отдельными backend повторно запускают скриптами из `eval/`.
- Python evaluator запускается в корне репозитория. Вывод отображается в панели,
  завершённый JSON автоматически появляется в графиках и истории.
- Активный эксперимент можно остановить кнопкой «Остановить».
- История: сохранённые отчёты, переход к результату и скачивание оригинального JSON. В графике можно выбрать варианты промптов и ONNX int8.
- Датасеты: реальные числа вопросов и документов, доступность файлов и описание корпуса.
- Кнопка `?` объясняет метрики. Непротестированные модели отображаются без чисел.

Результаты берутся из `eval/results/*.json`; поддерживаются отчёты evaluator,
вариантные отчёты моделей и сводный ONNX int8 отчёт. Демо-метрик в приложении нет.
Каждый запуск создаёт `dashboard_<uuid>.json`. Обновление данных — каждые 4 секунды.
Статусы и логи активных заданий хранятся в памяти Next.js; постоянная история — JSON-отчёты.
Приложение рассчитано на один локальный Node.js-сервер и один активный evaluator.

## Python и модели

Для просмотра сохранённых отчётов Python не требуется. Для запуска эксперимента
на macOS/Linux панель использует `.venv/bin/python`, если он существует, иначе
ищет `python3`. На Windows используется `.venv/Scripts/python.exe` или `python`.

Чтобы подготовить окружение Python на macOS, из корня репозитория выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Для моделей с backend SentenceTransformers дополнительно установите:

```bash
.venv/bin/python -m pip install sentence-transformers
```

Первый запуск модели может скачивать веса с Hugging Face. Датасеты и семантика
метрик совпадают с CLI `python -m eval.evaluate_embeddings`.

Обычно пути определяются автоматически. Если проект расположен нестандартно,
скопируйте `.env.local.example` в `.env.local` и задайте абсолютные пути, например:

```dotenv
EVAL_PROJECT_ROOT=/Users/you/path/to/RAG_abitura
EVAL_PYTHON=/Users/you/path/to/RAG_abitura/.venv/bin/python
```

## Проверка и сборка

```bash
cd eval/dashboard
npm run typecheck
npm run build
npm start
```

После запуска сервера `npm test` проверяет чтение/скачивание отчётов и валидацию API,
без запуска тяжёлой оценки.

Компоненты UI находятся в `src/components/ui/`, основной экран —
`src/components/dashboard.tsx`, чтение отчётов и запуск процессов — в `src/lib/`.

## Ответы из SQLite

Главный раздел «Ответы» отображает таблицу `answers`: ID, модель, вопрос,
ответ, модель-судью, ручную оценку и оценку LLM. Доступны поиск по всем полям,
страницы по 25 записей и полный текст через «Открыть». Сортировка по модели
или модели-судье доступна в обоих направлениях и применяется ко всем записям
до разбиения на страницы; пустые названия моделей располагаются в конце. Обновление — каждые 4 секунды.

База по умолчанию: `eval/domains/HPotter/answers.sqlite3`.
Чтобы выбрать другой файл, задайте абсолютный путь в `.env.local`:

```dotenv
EVAL_ANSWERS_DB=/absolute/path/to/answers.sqlite3
```

Для просмотра SQLite нужен Python 3: используется стандартный модуль `sqlite3`,
без установки дополнительных пакетов. Выбор Python определяется `EVAL_PYTHON`
или существующим виртуальным окружением проекта.

Старая таблица `users` переименовывается в `answers` с сохранением записей
при запуске из `eval`: `python3 RAG_HP.py --mode init-db`.
После этого можно импортировать Excel через `--mode import-db` или добавить
вопросы через `--mode generate`. GET `/api/answers` читает базу без записи.

Кнопка «Добавить новый вопрос» открывает форму с вопросом и моделью Yandex API.
Поля модели-судьи и оценок видны, но недоступны. «Добавить и получить ответ»
сначала сохраняет вопрос в SQLite, затем запускает существующий RAG по
`eval/RAG_data/HarryPotter.txt` и запрашивает ответ через Yandex API. Можно также
сохранить вопрос отдельно и позже нажать «Получить ответ». Готовые ответы не
перезаписываются; при ошибке вопрос остаётся в базе для повторного запуска.

Для генерации нужны зависимости существующего `RAG_HP.py` и серверные
`YANDEX_API_KEY`, `YANDEX_CLOUD_FOLDER` в окружении, `.env` проекта или `eval/.env`.
Их также можно задать в `dashboard/.env.local`. Ключ не передаётся браузеру.
Зависимости для генерации устанавливаются из корня проекта:
`.venv/bin/python -m pip install -r eval/requirements-rag.txt`.
Список предлагаемых моделей настраивается через `YANDEX_MODELS` (ID через запятую),
папка текстов — через `EVAL_RAG_DATA_DIR`; по умолчанию используется `eval/RAG_data`.

Фильтры «Ручная оценка» и «Оценка LLM» независимо выбирают все записи,
записи с оценкой или без неё. `NULL`, пустые строки и пробелы считаются отсутствием
оценки, текст `0` — заполненной оценкой. Фильтры применяются до пагинации.
Если отсутствует хотя бы одна оценка, доступна кнопка «Оценить».
В форме ручная оценка, LLM-оценка и название LLM-судьи вводятся вручную;
автоматического вызова модели для оценки пока нет. Можно сохранить только
недостающие поля: ранее введённые значения остаются на месте.

Интеграционные тесты записи запускаются с `EVAL_TEST_WRITES=1` только на сервере,
для которого `EVAL_ANSWERS_DB` указывает на отдельную тестовую базу.

«Загрузить кластер вопросов» принимает файл JSON со схемой
`{"request": ["вопрос 1", "вопрос 2"]}` или Excel `.xlsx`/`.xls` с единственным
заголовком `request` на первом листе в первой строке. Дополнительные столбцы
игнорируются, пустые клетки request пропускаются; вопросы должны быть текстом.
Один файл — до 10 МБ и до 500 вопросов. Все вопросы проверяются до записи;
затем кластер вставляется одной транзакцией без ответов, модели-судьи и оценок.

После выбора модели «Загрузить и получить ответы» запускает последовательную
обработку на сервере. Прогресс и ошибки видны над таблицей, ответы сохраняются
по мере получения. Закрытие окна или вкладки не останавливает обработку.
Очередь и прогресс хранятся в памяти локального сервера; при его перезапуске
сохранённые вопросы и ответы остаются в SQLite, незавершённые вопросы можно
обработать кнопкой «Получить ответ». Ошибка одного запроса не прерывает остальные.
